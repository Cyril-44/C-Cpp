# AtCoder Runner

一个可执行入口 `atcoder`，只依赖 Python 3.8+ 标准库。运行环境为 Linux / WSL，需安装并登录 Codex CLI；供 AI 测试样例的 `g++` 也要可用。运行时不依赖 Playwright。

`solver_prompt.md` 就是发送给解题 Codex 的提示词，可以直接编辑。程序替换其中的 `{{output}}`，设置题目目录为 Codex 工作目录，关闭网页搜索和沙箱网络访问。提示词要求 AI 使用 C++17，实际编译并验证全部样例，最终只写指定代码文件。外层程序不检查代码或样例结果，生成成功就提交。

## 使用

在项目目录执行：

```bash
chmod +x atcoder
./atcoder login alice
./atcoder run abc344 alice
./atcoder do abc344_a alice
./atcoder do abc344_a alice gpt-6-astra/xhigh
```

`alice` 是你自己起的本地账户别名，与 AtCoder 用户名无关。`login` 只保存这个别名和浏览器 Cookie 中 **REVEL_SESSION 的值**；省略第二个参数会在终端隐藏输入。也支持 `./atcoder login alice 'COOKIE值'`。凭据保存在根目录 `config.json` 中，文件权限为 600。多个别名可以分别保存不同账户。

`run` 以单比赛、单账户运行。首次访问比赛首页和题目列表，保存开赛时间、题数、分值、每题模型与思考深度到 `abc344/contest.json`。已有配置时复用。如果赛前题号未公开，先保存首页公布的题数、分值和模型，到开赛时获取正式题号。首页尚未公布的信息记为未知，未知分值使用默认模型。

比赛开始时，所有题并行抓取 `statement.md`，每题获取完成就独立启动 Codex。每题 Codex 正常完成后立即使用指定账户提交，不等待其他题；配置了 `cppobf` 时先混淆。再次运行或换账户运行时复用已有题面和 `sol.cpp`。

准备比赛读取首页和题目列表、抓取题面及题目图片失败时（包括 HTTP 429 和网络错误），等待 **5 秒**后重试，最多 **10 次重试**，即首次请求加重试共最多 11 次。准备信息或题面获取失败时，界面会显示失败原因和当前重试次数。每题独立等待，其他题仍可继续抓取、解题和提交；重试耗尽后显示该题失败，等待时可以退出。已有题面继续直接复用。

`do` 的 `problemid` 使用 AtCoder 正式题号，例如 `abc344_a`。优先提交已有的最新编号代码（`sol1.cpp`、`sol2.cpp` 等），没有编号代码时复用 `sol.cpp`，已有代码就不再调用 AI 或抓题，即使命令指定了模型也直接提交。没有代码时使用指定的 `MODEL/LEVEL` 或根配置 `default` 解题，写入编号文件并立即提交。题面已有就复用，已有题目锁时等待。`run` 也优先复用已有代码。

所有提交固定选择 **C++23**，语言编号从真实提交表单读取；发送表单中的 CSRF、题号、语言编号和完整代码，不等待评测结果。

代码文件写出后，Codex 可能还要编译、运行样例、修正代码和给出最终答复。程序等待整个 Codex 进程正常退出，随后进入混淆和提交，没有固定的一分钟等待。提交表单在解题同时预取；如果 Codex 已完成而表单还没取到，界面显示“等待提交表单”。程序不保存 Codex 的步骤日志，无法仅凭文件写入时间还原某一次收尾的具体耗时。

`run` / `do` 的终端界面实时显示北京时间（UTC+8）、本次运行用时、开赛倒计时和比赛已进行时间 / 总时长；赛程结束后显示已结束。AI 解题时题号前显示旋转动画，提交时显示跳动的向上箭头。默认使用鼠标：滚轮滚动题目列表，点击复制代码或顶部退出按钮；方向键、数字键和 `q` 仍可作为备用。鼠标使用 SGR 协议，支持宽窗口并兼容旧版终端库；复制在后台执行，界面保持响应。

总时长取自比赛首页的起止时间，使用 `start` / `end` 字段（Unix 时间戳秒数）保存到比赛目录的 `contest.json`；旧配置缺少结束时间时只补齐该信息，保留原有模型分配。`do` 在后台读取并缓存赛程，不阻塞抓题、解题或提交，不预获取题目和分配模型。仅有赛程配置时，之后的 `run` 会补全题目配置。

## 配置和目录

根目录 `config.json` 的 `default` 设置 `do` 和未知分值使用的模型；`rules` 按顺序匹配分值，区间为 **包含 min、不包含 max**，`max: null` 表示无上限。修改模型和深度直接编辑这些字段。`codex` 可指定 CLI 的绝对路径；`http_timeout` 和 `ai_timeout` 分别为网络请求、每题 AI 的超时秒数。

`cppobf` 配置为程序路径时，`run` / `do` 默认对提交代码执行 `--compress --flatten --opaque`，输出同目录的 `sol.obf.cpp` 或 `sol1.obf.cpp` 等；提交和复制都使用该文件。原始代码保留，已有代码直接提交时也会混淆。相对路径以项目根目录为基准，支持绝对路径；当前配置使用提供的 `./cppobf`（Linux / WSL，x86_64，依赖 LLVM/Clang 18 动态库）。省略该项或设为 `null` / 空字符串即可关闭。

```json
"cppobf": "./cppobf",
"cppobf_timeout": 30
```

混淆结果比源码和 `cppobf` 程序都新时直接复用；更新源码或工具后重新生成。混淆也在题目锁内执行，各题之间仍并行。`cppobf_timeout` 为每题混淆超时秒数，默认 30。混淆失败时显示错误并保留原始代码，部分输出会清理；只有混淆成功才提交，不回退提交原始代码。外层程序不编译或检查混淆结果。

```text
项目目录/
  atcoder
  config.json
  solver_prompt.md
  README.md
  cppobf
  abc344/
    contest.json
    .lock
    A/
      .lock
      statement.md
      sol.cpp
      sol.obf.cpp
      sol1.cpp
      sol1.obf.cpp
    B/...
```

隐藏的 `.lock` 使用操作系统文件锁；进程结束会自动释放，空文件保留以避免锁冲突。不同账户共享题面和代码生成，每个账户仍各自提交。没有 AI 日志、样例拆分文件或 Solution 文档。题面包含样例；有题目图片时，外层下载到临时目录并附给 Codex，结束后删除。

比赛配置一旦生成，就固定其中的模型分配。希望按新规则重新准备时，删除该比赛的 `contest.json` 后运行 `run`。

## Cloudflare

提交遇到 Cloudflare、登录页跳转或其他请求错误时，交互式终端会保留代码和该题的 **[ 复制代码 ]** 按钮，直到手动退出。提交页的登录跳转不直接判定会话无效。点击按钮复制完整提交代码（已开启混淆时为 `.obf.cpp`），滚轮滚动列表，点击顶部 **[ 退出 ]** 结束；数字键 1–9 对应当前可见的复制按钮。程序优先使用 `clip.exe` / `wl-copy` / `pbcopy` / `xclip`，否则发送 OSC 52 剪贴板请求。终端需要支持鼠标和相应的剪贴板方式。重定向输出或非交互式运行时无法显示可点击按钮，会打印代码路径并以非零状态退出。

没有登录、验证码处理或自动提交重试。若准备比赛或抓题也遇到验证，获取重试耗尽后显示错误；尚未生成代码时没有可复制的解答。
