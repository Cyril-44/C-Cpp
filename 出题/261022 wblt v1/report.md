# 《窗口校准》完整出题报告

发布版本：1.0。完成日期：2026-10-22（Asia/Shanghai）。

## 1. 设计目标与最终题意

本题以用户给出的区间复制、整除、求和维护题为设计原型，保留“可持久化共享结构与引用计数回收”这一核心。最终采用用户选定的二次版本：题面只给出滑动窗口和的约束，不出现区间复制、周期延拓或共享子树提示。

给定模 $P=998244353$ 的数组，操作一固定 $[l,r]$ 的前 $k+2$ 项，校准其余项，使长度为 $k$ 的所有窗口和的二阶差分恒定；操作二对原数组做区间仿射变换；操作三求区间和。操作一满足 $1\le k\le r-l-1$，结果存在且唯一。全局 $1\le n,m\le3\times10^6$，至少一次查询。所有输出取规范剩余类。

原型的除以二改成仿射变换，是为了让原数组修改能在二阶差分上变为区间乘法和常数个端点修正。对原数组直接整除不能按相同方式交换到差分层。本题的难点因此集中于数学转化、局部矩、共享平衡树和内存管理。

完整题面见 `statement.md`，包含三组样例、模数解释、退化情况和全部输入限制。

## 2. 正解与正确性依据

令 $e_i=a_i-2a_{i-1}+a_{i-2}$，补充 $a_0=a_{-1}=0$。相邻窗口的三阶差分为

$$\Delta^3W_i=e_{i+k+2}-e_{i+2}.$$

所以窗口条件等价于：$e_{l+2},\ldots,e_r$ 以原来的前 $k$ 项为周期。固定种子后递推唯一确定其余项，再积分恢复原数组，得到存在性和唯一性。

节点维护局部零基下标的三个矩 $M_0=\sum e_j$、$M_1=\sum je_j$、$M_2=\sum\binom j2 e_j$。前缀点值和前缀和分别为

$$a_t=tM_0-M_1,\qquad F(t)=\binom{t+1}2M_0-tM_1+M_2.$$

周期块通过“左右儿子引用同一根”倍增，再截取所需长度。标准程序使用叶子权重平衡树，按逻辑元素个数平衡，所有修改创建新路径，共享节点不原地改写。引用计数统计物理入边，旧根及临时根及时释放，并用空闲链表复用节点。

校准后不能遗漏右边界：设目标二阶差分段长为 $L$，零阶矩、一阶矩变化为 $dS,dT$，则 $dA=LdS-dT$，需对 $e_{r+1}$ 加 $-dA-dS$，对 $e_{r+2}$ 加 $dA$。仿射修改需四项端点修正，单点区间出现重合时必须累加。完整推导见 `editorial.md`。

总时间为 $O(n+m\log n)$，空间为 $O(n)$。一次释放可能级联回收大子树，因此这里是总时间/摊还保证，不宣称每次操作最坏都是 $O(\log n)$。

题目没有强制唯一数据结构。另写了直接维护原数组的持久化 AVL 参考程序，以局部一次位置函数为懒标记，不使用二阶差分、三个矩或上述端点公式；该程序也全部通过。它既是一条合法替代解法，也是独立的大数据答案校验来源。

## 3. 计分设计与实测部分分

采用组内全部通过才得分，各组无依赖、分数相加。令 $N=\max(n,m)$。

| 组 | 分数 | 点数 | 限制 |
| :--: | --: | --: | :-- |
| 1 | 20 | 8 | $N\le2000$ |
| 2 | 15 | 6 | $N>2000$，无操作一 |
| 3 | 15 | 7 | $N>2000$，有操作一且所有 $k=1$ |
| 4 | 20 | 8 | $2000<N\le20000$，有 $k>1$ 的操作一 |
| 5 | 30 | 11 | $N>20000$，有 $k>1$ 的操作一 |

这五组互斥并覆盖所有合法输入。正式 30 秒、512 MiB 下的实际评分如下；失败组在首个失败点后停止，该组按规则计零分。

| 实现 | 通过组 | 实测分数 | 首要失败原因 |
| :-- | :-- | --: | :-- |
| `std.cpp`：二阶差分 WBLT + 引用计数 | 1–5 | 100 | 无 |
| `reference_avl.cpp`：原数组 AVL + 位置标记 | 1–5 | 100 | 无 |
| `brute.cpp`：直接窗口递推 | 1、4 | 40 | 第 2、3、5 组超时 |
| `partial_special.cpp`：特殊校准线段树，一般校准模拟 | 1–4 | 70 | 第 5 组超时 |
| 标准程序关闭回收（`NO_GC`） | 1、4 | 40 | 第 2、3、5 组超过 512 MiB |

**分档说明：** 前三组为专用线段树提供 50 分基本覆盖，但它在中档数据上还能拿到额外 20 分，实际是 70 分实现。常数较小的 C++ 暴力也通过第 4 组，实际是 40 分实现。题解和 README 已按这一实测结果说明，没有把它们标成严格的 20 分或 50 分程序。第 4 组也允许使用不回收的共享树，最终大组再检验一般操作和空间管理。

## 4. 正式数据

交付 **40 组正式输入和 40 份答案**，另有 3 组公开样例。正式数据合计 18,456,329 次操作、2,610,174 个查询。输入共 583,309,176 字节（556.29 MiB），答案共 22,529,179 字节（21.49 MiB，规范 LF 换行）。其中两个点同时达到 $n=m=3,000,000$。

主要覆盖：最小数组和长度 3/4 区间；$k=1$、$k=\text{长度}-2$ 的恒等校准、只改变一项的校准；两端越界截断与单点仿射的修正重合；零、取负、单位及随机仿射参数；大/小周期、非整周期尾部、不同偏移；二次多项式固定点；素数和 2 的幂附近长度；嵌套共享后局部修改；反复覆盖与回收。

专门补充 `g5_preserved_seed`：前半区的大随机种子长期不变，后半区反复按不同大周期校准并局部仿射。它避免随机初值很快被全局短周期校准压缩，针对深拷贝、显式展开和不回收实现。各大组的首个“分组认证”操作也采用最短恒等校准，保留初值的多样性。

每点种子、规模和构造目的记录在 `config/data_spec.json`。生成器流式写出，不在内存保存全部操作。Windows Python 3.13.14 与 WSL Python 3.8.10 重生成小点、中点和百万操作的大种子点，SHA-256 均一致；生成器及规格指纹与生成清单一致。其他点也具有固定种子，未将未重复生成的点描述为已跨版本逐点复现。

## 5. 验题证据

1. **数学检查：** 对 $n\le5$、初值来自 $\{0,1,P-1\}$ 的全部合法校准枚举 2,781 组；另做 10,000 组随机公式检查，核对原数组、差分更新、窗口条件和每个前缀的矩重建。
2. **直接题意对拍：** Python 窗口和闭式 oracle、独立 C++ 窗口递推暴力、开启结构审计的 WBLT，在 5,010 个用例、2,530,586 次操作、2,047,716 个答案上全部一致。
3. **独立 AVL 对拍：** 新种子下 3,010 个用例、2,012,743 次操作、1,679,110 个答案，与题意 oracle 和 WBLT 一致；同时审计 AVL 平衡、懒标记和引用计数。
4. **树结构检查：** 100,000 次结构随机操作；穷举至 14 个逻辑叶子的 11,110 个平衡形状，完成 156,955 次分裂重拼、29,983 次有序拼接、15,900 次共享重复检查。
5. **内存/未定义行为检查：** GCC 10.5.0，ASan + UBSan + 每操作 DAG 审计，510 个用例、404,092 次操作、343,466 个答案全部通过，未报告 sanitizer 错误。
6. **部分分程序：** 三个样例和 600 个独立随机用例通过；正式前四组也逐点核对通过。大随机种子策略另做 54 个缩小变体的三程序对拍，全部一致。
7. **输入/输出工具：** validator 的 75 项正反例全部通过，并用正式构建重新回放；checker 的 15 项正反例全部通过。所有 40 点均按明确分组及规模校验，所有答案数量与输入校验器统计的查询数一致。
8. **全量大数据：** Windows、Linux 各自完整运行两份独立标准程序。两环境的 40/40 点均通过，所有答案逐 token 一致。初始答案规范为 LF 后，又与保存的四套输出逐点复核。
9. **错误实现检查：** 9 个故意错误版本全部被样例或正式小数据击中；关闭回收版本在正式 512 MiB 限制下被判 MLE。

这些是程序化验题和独立实现交叉检查；没有把子代理审查称作真人试做。尚未组织真实参赛者的限时试做，因此题目区分度和人类完成时间没有实测结论。

## 7. 实测性能与正式限制

机器：Intel Core i7-14650HX，32 GB 内存。Windows 构建使用 MinGW-w64 GCC 15.2.0；Linux 为 Ubuntu 20.04 / WSL2 x86_64、GCC 10.5.0。正式解按 C++17、`-O2 -DNDEBUG` 构建，验题额外启用 `PROFILE`，统计只写 stderr。

正式发布配置为 **30 秒、512 MiB、64 位 C++17**。完整验收运行器曾以 120 秒作为诊断上限，但两份满分实现实测均低于正式 30 秒；部分分评分和不回收对照实验实际使用 30 秒、512 MiB。

耗时为墙钟时间，包含程序启动和输入输出。Windows 内存取系统的峰值工作集；Linux 每 10ms 采样 `/proc` 中的 VmHWM/VmRSS，极短点可能漏采启动后的峰值，不能将其很小的记录当作精确内存需求。长时间大点的峰值已覆盖，节点池字节数也单独记录。Linux 是 WSL2 测试环境，不是独立裸机评测服务器；迁移到实际 OJ 时应按本包基准重测时限。

## 9. 交付文件与复验

- `statement.md`、`editorial.md`、`report.md`、`README.md`：题面、完整题解、本报告和使用说明。
- `solutions/`：WBLT 标准程序、独立 AVL 参考、直接暴力、部分分线段树。
- `samples/`：3 组公开样例和解释。
- `data/`：40 组正式输入、40 份 LF 答案、固定种子生成清单。
- `config/`：分组、构造规格、平台中立的正式评测参数与逐组文件映射。
- `tools/`：构建、生成、validator、checker、对拍、结构测试、变异测试、实际评分和完整性检查。
- `audit/`：上述各层测试的原始 JSON 记录、数学审查、数据设计和关键反例。
- `manifest.json`、`checksums.sha256`：发布文件大小和 SHA-256 校验和。

在题包根目录可执行以下命令。示例为 Linux；Windows 可执行文件加 `.exe`，并可用 `--cxx` 指定 64 位编译器。

```text
python3 tools/build.py --out build --audit --no-gc
python3 tools/check_integrity.py
python3 tools/generate.py --all --output-dir data
python3 tools/verify_package.py --std build/std --reference build/reference_avl --validator build/validator --brute build/brute --partial build/partial_special --scratch build/verify --write-answers --timeout 30 --memory-mb 512
python3 tools/oracle_fuzz.py --std build/std_audit --reference build/reference_avl_audit --brute build/brute --cases 3000
python3 tools/score_solution.py --exe build/partial_special --work build/score --report build/score.json --timeout 30 --memory-mb 512
```

答案生成要求传入独立参考程序，只有核对一致后才发布 `.ans`。源代码轻量包省略正式 `.in/.ans`，使用 `check_integrity.py --skip-data` 校验，再按固定种子生成数据。完整包已包含全部正式数据，无需重新生成即可使用。

题包是平台中立的交付格式，没有冒充已经导入某个 OJ；`config/judge.json` 给出正式时空限制、checker 约定和每组输入输出映射，组分数总计 100。

## 10. 验收结论

本版本的题面、唯一性证明、满分算法、两份独立实现、部分分、正式数据、答案、校验工具和可复验记录均已完成。正式数据在两个执行环境上全部核对通过。分档效果按实际 40/70/100 分路线记录；30 秒、512 MiB 为本次实测后的发布配置。剩余的人类试做与具体 OJ 导入不在本次已执行验题结果之列。

权重平衡树 join/split 的通用复杂度背景参考：[Blelloch、Ferizovic、Sun, Joinable Parallel Balanced Binary Trees](https://www.cs.cmu.edu/~blelloch/papers/3512769.pdf)。窗口转化及端点公式已在题解和数学审查中独立推导。
