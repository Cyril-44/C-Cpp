# ring：叶环独立集（出题报告）

## 定位与核心考点

本题在树的 DFS 叶序上增加一个环，要求统计独立集。预期考查树形 DP、子树叶序连续性，以及有序子问题合并时保留首尾边界的状态设计。面向提高组，核心思维难点在于找到常数大小的边界，代码量和实现细节适中。

普通树独立集只记录根选或不选；本题还记录子树首叶、末叶的选取状态，共 8 个状态。依孩子编号顺序合并时，只新增一条跨边界叶子边，最后在根补上首尾闭环约束。单叶不补边，两叶的重复边不改变约束。每个独立集唯一对应各子树的状态及分解，因此既无漏计也无重计。完整转移与归纳证明见 `sol/solution.md`。

标准解时间 O(n)、空间 O(n)，按编号从大到小计算，避免百万长链上的递归栈溢出。主要数组约 44 MB；乘法用 64 位整数。题面限制为 **5 秒 / 128 MiB**。此前完整验题中标准程序实测最大 0.12 秒、46216 KiB RSS；计时依赖本机，发布前仍应按目标评测机复核限时。

## 统一目录

- `statement.md`：完整题面，含样例和分组评分。
- `sol/std_boundary_dp.cpp`：8 状态线性标准程序。
- `sol/partial_15_bruteforce.cpp`：枚举顶点集合的 15 分程序。
- `sol/partial_25_few_leaves.cpp`：枚举叶子状态的 25 分程序。
- `sol/partial_15_star.cpp`：星形树的 15 分程序。
- `sol/solution.md`：题解、正确性证明和复杂度。
- `gen/gen.cpp`、`gen/val.cpp`、`gen/genall.sh`：固定种子 testlib 生成器、严格格式及分组校验器、一键生成 Bash 脚本；`gen/cases.tsv` 保存正式与下发数据的完整生成计划。
- `review/reference_matrix.cpp`：逆序孩子合并的独立矩阵参考。
- `review/check.cpp`：testlib 整数输出 checker，忽略空白并拒绝多余 token。
- `review/run_tests.py`：算法对拍、样例与非法输入检查、数据生成复核；直接编译 `sol/` 中的暴力程序，验题样例读取下列独立文件。
- `review/statement_sample.in`、`review/statement_sample.ans`：保留的独立验题样例输入、答案，与当前下发 `ring1` 逐字节一致。
- 最终正式数据位于题目目录的 `../../data/ring/`，下发样例位于 `../../down/ring/`；编译产物与临时文件只在忽略的 `review/.build/`。

## 数据分组与目的

| Subtask | 分值 | 条件 | 测试点 | 主要覆盖 |
|---|---:|---|---|---|
| 1 | 15 | n<=20 | 01_01..01_08 | 最小规模、单叶、双叶、星、平衡、8叶、随机、随机二叉 |
| 2 | 25 | n<=100000，叶子<=8 | 02_01..02_08 | 长单链/双叶/3叶/8叶、随机少叶树、交错编号、最小8叶骨架 |
| 3 | 15 | 根为中心的星 | 03_01..03_04 | 最小星、奇偶叶数、百万上界 |
| 4 | 45 | 无额外限制 | 04_01..04_10 | 百万链、双叶、平衡、梳、扫帚、随机、随机二叉、999999边界、百万少叶 |

每点输入命名为 `01_01.in` 等，输出为同名 `.ans`；采用 Subtask 整组计分。`gen/cases.tsv` 给出每个输入的目标目录、文件名、分组、形态、n、种子和叶数参数（`-` 表示不适用），由生成脚本和复核脚本共同读取。生成计划只保存在 `gen/`，正式与下发输出目录只生成 `.in/.ans`。各组允许重叠，但分值和适用范围均单独说明。

下发样例共 6 组，均包含 `.in/.ans`：`ring1` 与题面原有样例逐字节一致（n=7，答案21）；原5组大样例依次顺延，`ring2` 为10万链，`ring3` 为10万随机8叶树，`ring4` 为百万星，`ring5` 为百万随机树，`ring6` 为百万随机二叉树。原正式数据及5组大样例的输入、答案内容不变。

## 生成与校验

依赖 Bash、git、g++（C++17）、Python 3、GNU time；**gen/val/checker 只使用 git 根目录 `/home/cyril/code/testlib.h`**，不依赖个人目录中的其他 testlib。

从任意工作目录调用脚本均可：

```bash
bash /path/to/dev/ring/gen/genall.sh
bash /path/to/dev/ring/gen/genall.sh "/custom/data with spaces/ring" "/custom/down with spaces/ring"
```

默认路径相对于 `dev/ring` 题目目录解析；用户提供的相对路径相对于调用时的工作目录解析。脚本先在本题临时目录生成30组正式数据和6组下发数据，用对应 Subtask 的 testlib 校验器校验并运行标准程序产生答案。下发前缀 `ring1` 直接从 `statement.md` 提取原样例输入、输出，输入通过 testlib，标准程序答案还须与题面输出逐字节一致。全部成功后只复制 `.in/.ans` 到最终目录。它覆盖本题生成的同名文件，**不会删除传入目录中的无关文件**，也不会向输出目录写入生成计划或其他文件；所有下发 `.in/.ans` 的权限设为 **664**。两个目标目录必须不同。每次随机种子显式固定。

```bash
python3 /path/to/dev/ring/review/run_tests.py
python3 /path/to/dev/ring/review/run_tests.py --generation-only --check-generation
python3 /path/to/dev/ring/review/run_tests.py --skip-large --exhaustive-max-n 5 --random 8
```

完整自测编译所有程序，穷举 n=4..8 的 5910 棵递增父编号树，随机对拍，再按 `gen/cases.tsv` 验证全部正式/下发数据的答案、分组和可复现性，并复核下发样例前缀与保留的独立验题样例一致。独立矩阵参考从逆序孩子合并，得到整体叶序反转，利用无向环在反转下不变检查标准实现的有序合并。参数 `--check-generation` 还会实际完整生成到含空格的相对自定义目录，验证36对文件与默认输出逐字节一致、没有附加生成文件、无关输入与嵌套文件保留，以及下发权限664。`--generation-only` 只编译 gen/val/std，复核生成计划、36对输入/答案、题面前缀、固定种子复现和输出目录内容，不运行算法对拍。`--skip-large` 可只跑小规模算法测试，`--data`、`--down` 可指定待审计目录。检查结果与耗时摘要只输出到终端，不生成报告或哈希清单。

## 风险及当前结论

必须特判单叶不添加自环；双叶重复边无需重复计数；不能按顶点编号代替 DFS 叶序，不能忽略闭环边。百万深链要求迭代实现，且标准程序不能为每个顶点保存大矩阵或显式集合。以上边界均有穷举或正式数据覆盖。当前没有已知正确性或数据格式遗留问题。此前完整算法复核通过了 5910 棵穷举树、400 棵固定种子随机树、全部 10 种生成模式共 40 例，以及30组正式数据和原5组大样例的独立参考与适用部分分交叉检查；生成流程复核通过了当前36组输入/答案的校验、逐字节复现和自定义路径检查，下发文件权限均为664。
