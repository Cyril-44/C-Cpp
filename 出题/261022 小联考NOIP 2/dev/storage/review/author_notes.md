# 《存储空间》出题说明

本文保留原 v2 版命题设计。文末性能是旧 Windows 测量；本次 WSL 复测见 `benchmark.json`，最新操作方式见本目录 `README.md`。

## 定位与结构

本题面向已掌握树链剖分和动态树 DP 的选手。主要难点不在局部 DP，而在把一次可能产生线性多个规范需求的区间操作，压缩成少量可批量处理的修改。

完整算法需要依次建立这些联系：

1. 层级区间的精确覆盖，等价于覆盖规范分解中的节点。
2. 规范分解可由最高包含祖先和两条边界路径表示。
3. 让状态忽略自身需求，可把大量兄弟节点的需求变化留在边界路径上的父节点处理。
4. 重链矩阵依赖轻孩子计数是否为零；非负计数的最小值与四种假想乘积支持统一加减。
5. 同一次区间操作的传播路径只有两条，统一批处理才能去掉额外一层对数。

任意树形让规范分解可能线性增长；任意正费用则使“买当前节点”和“买子孙节点”真正需要比较费用，不能复用单位费用下只看可见标记数量的公式。

题解给出的 $O(n+q\log^2 n)$ 算法不要求保存 $O(n\log n)$ 的倍增表。最高包含祖先与 LCA 均可使用已有重链信息完成，整体空间保持线性。

## 子任务设计

十档分值为 `5,10,10,5,10,10,10,10,5,25`，合计 100 分，各档独立、组内全过得分。

- 第 1 档允许独立枚举节点集合，不需要理解树形 DP。
- 第 2 档允许每次全树重算，验证静态状态定义与加权方案计数。
- 第 3、4 档限制高度，可以直接沿实际区间边界递归维护。
- 第 5 档仅有规范节点点修改，只需普通动态树 DP。
- 第 6 档为右梳状树，只有一条内部重链与一种方向的区间计数。
- 第 7 档固定右重孩子方向，保留多链传播，但只需两种假想乘积。
- 第 8 档仅有插入，可以跳过已激活需求并摊还处理首次变化。
- 第 9 档为长度不超过 2 的需求，存在独立的加权双叶组件算法。
- 第 10 档覆盖完整问题。

第 9 档最终采用区间长度不超过 2，而不是早期的 `q <= 2000`。后者只能自然导向至多 $2\times10^8$ 次全树状态计算，是否得分过于依赖尚未最终确定的时限；双叶组件限制具有明确的 $O(n+q)$ 解法。

### 第 7 档的方向简化

每个节点的右子树叶子数都不少于左子树，且平局时选右孩子为重孩子，因此每个轻孩子都在左侧。维护结构只需一个最小值与两种假想乘积。

这不意味着整棵树只有一条链：左侧轻子树仍可能包含许多节点。必须保留多链之间的状态传播，并在一次区间操作内统一处理相关链，才能维持 $O(\log^2 n)$ 单次复杂度。

### 第 8 档的摊还界

只维护“曾被规范需求过”的布尔值是正确的，因为之后没有删除。为避免重复枚举大量旧块，需要按两种方向维护尚未激活的轻孩子位置集合。

每个边界链区间做一次有序集合定位，所有操作共 $O(q\log^2 n)$。每次有效激活立即移除相应位置，并用普通点修改动态树 DP 更新；整棵树至多发生 $2n-1$ 次首次激活，因此这部分共 $O(n\log^2 n)$。端点或重孩子的独立点激活也必须更新同一个布尔状态；轻孩子若由点操作激活，也应从未激活位置集合移除。

直接枚举每次规范分解再判断是否已激活，仍可能退化到 $\Theta(nq)$，不能算作这一档的高效解法。

## 应覆盖的错误实现与构造方向

| 错误或薄弱点 | 适合的测试 |
| --- | --- |
| 直接枚举规范块或沿原树逐祖先更新 | 线性深度左右梳状树，反复加入删除大区间 |
| 不先取最高包含祖先 | 只需求某个完整内部节点，且购买该节点更便宜或与子孙平局 |
| 边界路径错误包含父亲为 LCA 的边 | 两端在不同分支、目标又不等于整个 LCA 区间 |
| 两端规范块相同时重复计数 | 整段、单点和精确节点区间的增删 |
| 删除时清除布尔标记 | 两个不同原区间共享规范块，删除其一后另一个仍活动 |
| 假设所有轻孩子在同一侧 | 重孩子方向交替变化的树，并让更新跨过两种位置 |
| 遇到大批零与正切换时逐点处理 | 长链区间反复整体加一、减一 |
| 一次链修改就单独向根传播 | 两边界经过多条重链，且相关传播大量重合 |
| 忘记轻子链变化后重建父位置的全部模式 | 保持父计数正值，反复改变其轻子树内部需求 |
| 将轻孩子计数下传到其子树 | 一个完整节点的需求，购买该节点优于进一步细分 |
| 将计数模后为零当作不可行 | 检查状态处理逻辑；可行性只能由费用哨兵判定 |
| 费用用 32 位整数 | 大量单点需求，叶子费用接近 $10^9$ |
| 只比较费用而忽略方案数变化 | 保持费用不变、但让两类等价最优方案出现或消失 |
| 按编号倒序当作后序 | 固定根为 1，随机置换其他节点编号 |
| 把节点编号当作叶子区间序号 | 多层结构与置换编号，查询不连续节点编号对应的连续叶序 |
| 递归遍历深树导致栈溢出 | 最大规模梳状树 |
| 长度 2 子任务跨组件只用布尔值 | 两个相邻长度 2 区间共享叶子，随后删除其中一个 |

用于方案数增长的简单构造：选取许多互不相交的双叶组件，父费用为 2、两叶费用各为 1，每个组件只加入父区间需求。每个组件有两种最优存储集合，整体方案数为 $2^k$，可以检验取模和组件间的乘法。

不要仅因为某实现写成 $O(\log^3 n)$ 或多一个对数，就假定它必然超时。应使用实际最大规模测试比较运行时间，再确定最终限制。

## 标准解的重要不变量

1. $X_v,B_v$ 忽略 $c_v$；父亲决定使用哪个状态，根计数单独决定答案。
2. 轻孩子的需求次数保存在父位置；修改它不会改变轻子链报告的 $(X,B)$。
3. 每个非根节点的逻辑需求次数，只由其父亲的重孩子计数或轻孩子计数结构维护，不能出现两套不同步的真值。
4. 方向最小值始终非负；整段平移不改变取到最小值的位置，四种假想乘积因此可保持不变。
5. 某方向不存在时不执行加减，不能污染不存在方向的最小值哨兵。
6. 点重建前下放计数结构的懒标记；重建后按真实区间顺序合并矩阵。
7. 一次操作先完成直接更新，再按链头从深到浅汇总；每条相关链只报告一次。
8. 链头状态相等的判断包含费用与模后的方案数，二者都相等才能停止此次报告。
9. 不可行状态为无穷大费用、零方案数；方案数为零的有限费用状态仍然可行。
10. 初始空需求时，$X$ 为 $(0,1)$，但内部节点的 $B$ 必须通过加权 DP 计算。

## 评测移植与限制

当前建议配置为 10 秒、256 MiB。完整数据集已在本机运行并核验；5 组代表性用例各重复 3 次，最慢一组中位数约 6.14 秒，最大采样峰值工作集约 105.5 MiB。详细环境及每次测量见 `previous_reports/benchmark.json`。迁移到目标评测环境后应重新确认限制。

移植时应统一 C++17 与优化选项，记录编译器、体系结构和评测机器信息；分别统计最大输入的运行时间与峰值内存。费用字段使用 64 位整数，乘法取模也需 64 位中间量。

矩阵维护的常数空间较大。紧凑线段树可以只分配约两倍实际位置数的维护节点；将四个矩阵的费用与计数分开存放，可避免每个二元组的对齐浪费。应以进程实测峰值确认 256 MiB 的余量。

验证器需要检查整棵树连通合法、根编号、零或两个孩子、实际叶子数、任意编号、权值范围和在线集合合法性。第 9 档应检查每次操作的区间长度，不再检查操作次数不超过 2000。

输出按整数 token 比较，接受正常空白差异；应拒绝少行、额外 token、错误费用以及未按模数范围输出的方案数。具体运行方式以本题包实际工具的命令行接口为准。
