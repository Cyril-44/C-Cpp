# 数据生成与覆盖设计

本文件描述 `tools/gen.py` 和 `tools/case_plan.json`。计划包含 **45 个私有用例、2 个公开大样例**；公开大样例均为 `n=q=100000`。计划本身不表示对应输入、标准输出已经生成，实际生成及验收记录应由题包构建流程另行记录。

## 生成器接口

仅依赖 Python 标准库。示例：

```text
python tools/gen.py --n 100000 --q 100000 --shape zigzag_comb --mode adversarial --weights large --seed 2026102192 --out data/public/large_sample_02.in
python tools/gen.py --self-test
```

必要参数为 `--n`、`--q`、`--out`。其余参数有默认值，但评测计划为每个用例显式记录了全部参数。

额外参数 `--numbering` 支持 `random`、`preorder`、`reverse`，默认 `random`。根始终编号为 1，其余节点可被随机重排。`reverse` 反转除根以外的分配编号；`preorder` 明确按树的先序排列编号。

输入输出格式为：第一行 `n q`；随后 `2n-1` 行左右儿子编号和正费用；最后 `q` 行合法集合增删。叶子的左右儿子均为零。叶子位置由树的中序左右顺序确定，与节点编号无关。

生成后，文件内容只包含题目输入。生成器把参数、最大叶深和输出文件位置写到标准错误，便于构建脚本记录。

## 树形

| `--shape` | 构造与覆盖目的 |
|---|---|
| `mid` | 每个节点严格按 `floor((l+r)/2)` 划分；左叶数为总数的上取半，覆盖第 3 档 |
| `random` | 在每个内部节点随机选择一个合法分点，产生多层不同轻重方向 |
| `left_comb` | 每个内部节点右儿子是叶子，树深可达 `n-1` |
| `right_comb` | 每个内部节点左儿子是叶子，符合第 6 档 |
| `zigzag_comb` | 每一层交替将大子树放左或放右，树深可达 `n-1`，持续切换同胞方向 |
| `heavy_right` | 每个节点保证右子树叶数不少于左子树，符合第 7 档；包含大小相等的情况 |
| `bounded30` | 构造时保留剩余深度所需的叶容量，保证最大叶深不超过 30，覆盖第 4 档 |

树的构造、重新编号、结构审查均为迭代实现，不依赖 Python 递归深度。

## 操作模式

| `--mode` | 内容与保证 |
|---|---|
| `random` | 随机区间、短区间、前后缀混合；删除会优先从活动集合抽取；活动集合最多约 512 个，避免很早完全饱和 |
| `mixed` | 随机区间、整段及树节点混合；活动集合最多约 256 个，持续触发稀疏状态变化和链头传播 |
| `node_only` | 所有区间恰好对应输入树节点，符合第 5 档 |
| `insert_only` | 只插入此前未出现过的区间，符合第 8 档；有限次随机尝试失败后用单调枚举兜底 |
| `root_singleton` | 整段需求存在时按序激活全部单点，再逆序移除，随后移除整段并循环；`n=1` 单独处理去重 |
| `alternating` | 两个共享规范块的不同原区间反复交错增删，检查需求计数是否真正过零 |
| `adversarial` | 共享规范块删除次序、批量双叶平局、孩子状态改变、非根节点完整边界与随机区间组合 |
| `short` | 所有区间长度不超过 2，符合第 9 档；先制造短区间引用及大量双叶平局，再随机增删 |

`random`、`mixed` 的活动集合上限是为了持续产生真实状态变化，并非题目约束。其他模式可积累较大的活动集合。

所有模式统一采用集合状态决定该次操作是插入还是删除，因此不存在删除未激活区间、重复插入活动区间的问题。仅插入模式额外保证选出的区间不在活动集合中。

当 `insert_only` 的 `q > n(n+1)/2` 时，生成器明确拒绝该参数组合。它不会靠无限重试等待不存在的新区间。计划中特意包含 `n=500,q=100000`，接近区间总数，检查碰撞与枚举兜底。

## 费用

| `--weights` | 规则 |
|---|---|
| `unit` | 全部费用为 1，便于和最小节点数模型核对 |
| `random` | 混合小整数、中等费用和接近 `10^9` 的费用，制造不同转移胜负 |
| `large` | 每个费用处于 `[999000000,1000000000]`，迫使答案使用 64 位整数 |
| `tie` | 节点费用等于其叶子数，因此父节点费用恰好等于两个孩子的费用之和 |

`tie` 模式有可解释的平局来源：只有整段需求时，选择当前节点或分别覆盖两个孩子可以具有相同总费用。许多独立分支同时产生平局，方案数很快超过模数。

长度为 2 的真正树节点也是计数回归点：单位费用下，同时要求父节点和其中一个叶子，最小费用为 2、最优集合数为 2；`tie` 费用下，仅要求这个父节点，最小费用为 2、最优集合数同样为 2。`short` 模式按这两种规则批量构造独立组件。

`case_plan.json` 的 `cases` 为私有用例，`large_samples` 为公开大样例；`cli_fields` 给出传给生成器的参数字段。每个用例还记录 `id`、`subtask`、`input`、`answer` 与设计目的。

|---|---:|---|---|
| 1 | 4 | `n<=7,q<=100` | 枚举核对、根即叶子、空集、任意编号、费用平局 |
| 2 | 4 | `n*q<=2000000` | 完整重算可得分；兼有大 `n` 小 `q` 和小 `n` 大 `q` |
| 3 | 4 | 精确中点树 | 二次幂及非二次幂、重复引用、大量平局、完整单点填满再清空 |
| 4 | 4 | 最大叶深不超过 30 | 有界深度但任意分点，避免把“深度小”误当“中点树” |

| 7 | 4 | 每个节点右叶数不少于左叶数 | 重儿子统一在右，包含左右大小相等及最大深度梳状树 |

| 10 | 9 | 无额外限制 | 深交替链、左右极端链、随机分叉、稀疏活跃中点树、正费用矩阵平局 |

## 必须出现的结构性错误区分

1. **共享规范块的引用计数。** 选择一个父节点，其一侧子树至少有两个叶子。取另一侧完整子树区间 `A`，再向较大一侧扩张一个叶子得到 `B`。`A` 与 `B` 都在规范分解中引用同一个完整节点，但 `B` 尚未包含整个父节点。交错插入、删除二者，能检查非零计数被错误清零的实现。
2. **两个零计数类别。** 交替链和共享引用模式使当前节点需求、相邻轻儿子需求分别发生零与正数之间的切换，覆盖矩阵乘积中的不同类别。
3. **非根端点的最高完整祖先。** 数据包含内部节点的完整区间、删去一个端点后的区间，以及向外扩张一格但未含父节点的区间；不能只在根或叶子层处理边界。
4. **祖先计数不变、孩子答案变化。** 整段需求保持激活时改变单点或深层需求，防止仅在当前计数过零时更新答案。
5. **最小费用相同、方案数变化。** `unit` 和 `tie` 的双叶结构及多层分叉同时验证计数传播。
6. **方案数取模。** 成千上万个独立组件会产生指数级最优集合数；不能依赖自然整数不溢出。
7. **64 位最小费用。** 大量活动叶子的费用总和可接近 `10^14`。
8. **任意编号与极深树。** 默认随机重排非根编号；部分用例反转编号；最深树达到 99999 层，要求实现避免深递归栈。
9. **避免满规模数据早饱和。** 满分组另有 `mid+mixed+tie`，活动需求保持稀疏并频繁变化；不能只用所有叶子很早都被永久要求的测试估计性能。
