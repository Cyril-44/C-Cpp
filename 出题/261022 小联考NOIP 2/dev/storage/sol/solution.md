# 存储空间 题解

下面按 [std_hld.cpp](std_hld.cpp) 的实现顺序讲解。完整算法为 $O(n+q\log^2 n)$ 时间、$O(n)$ 空间；先弄清“改哪些需求”和“需求如何影响 DP”，再把两部分接起来。

## 1. 先把原区间变成节点需求

对目标区间 $[l,r]$，取完整包含于它、且不能继续向父亲扩大的树节点。这些节点称为规范分解。例如八个叶子的完全二叉树上，$[2,7]$ 分成

$$
[2,2],\quad[3,4],\quad[5,6],\quad[7,7].
$$

满足这个目标，等价于分别完整覆盖这些块。维护

$$
c_v=\text{当前有多少个原区间的规范分解包含节点 }v.
$$

DP 只关心 $c_v$ 是否为零，但增删时必须保存完整次数。例如四个叶子的完全二叉树上，$[1,3]$ 与 $[1,2]$ 都会需求节点 $[1,2]$；删除前者后，这个节点仍有一次引用。

一次规范分解可能有线性多个块，不能直接枚举。关键是：**除了左右端点所在的块，其余块都是两条边界路径旁的兄弟子树。** 把这些兄弟的计数放在路径上父亲的位置，就能用重链区间修改。

## 2. 先写出能重算的树形 DP

每个状态用 `Value{cost, ways}` 保存最小费用及其方案数。两个独立部分合并时，费用相加、方案数相乘，记为 $\otimes$；两个互斥方案择优时，保留较小费用，平局则加方案数，记为 $\oplus$。方案数模 $998244353$。

| 状态 | 需要满足什么 |
| --- | --- |
| $X_v$ | 子树内所有严格子孙的需求，暂不要求覆盖整个 $I_v$ |
| $B_v$ | 同样满足子孙需求，并且完整覆盖 $I_v$ |
| $A_v$ | 实际使用的状态：$c_v=0$ 取 $X_v$，否则取 $B_v$ |

叶子有 $X_v=(0,1)$、$B_v=(w_v,1)$。内部节点的左右孩子记为 $L,R$：

$$
X_v=A_L\otimes A_R,\qquad
B_v=\bigl((w_v,1)\otimes X_v\bigr)\oplus(B_L\otimes B_R).
$$

`B` 的两个候选分别是“购买 $v$，子孙需求另外满足”和“不购买 $v$，完整覆盖两个孩子”。购买一个祖先不能代替对较小目标的精确覆盖，所以第一项仍然要加上 $X_v$。

例如父节点费用为 $2$，两个叶子费用均为 $1$。只需求父区间时，选父亲、选两个叶子都是费用 $2$，共有两种方案；再需求左叶子后，选父亲还得加买左叶子，费用变成 $3$，最优只剩两个叶子这一种。这个例子同时说明了祖孙需求与平局计数。

实现里不必保存 `A` 数组，用到孩子时根据其计数选择 `X/B` 即可。尤其要让 **$X_v,B_v$ 都不依赖 $c_v$**：改变 $c_v$ 只改变父亲怎样使用它，不必重算 $v$ 的整棵子树。根没有父亲，答案单独取 `rootCount ? B[1] : X[1]`。

## 3. 把重链上的 DP 写成矩阵

按子树叶子数选择重孩子，平局选右孩子。设 $v$ 的重孩子为 $h$、轻孩子为 $s$，先把轻子树贡献记为

$$
C=(c_s=0\ ?\ X_s:B_s).
$$

先固定轻孩子的贡献 $C,B_s$。重孩子无需求时，$X_v=C\otimes X_h$；有需求时，$X_v=C\otimes B_h$。再把 $B_v$ 的转移按 $X_h,B_h$ 归类，便得到矩阵的第二行：

$$
\begin{pmatrix}X_v\\B_v\end{pmatrix}
=M_v\begin{pmatrix}X_h\\B_h\end{pmatrix},\qquad
M_v=
\begin{cases}
\begin{pmatrix}C&\mathbf0\\(w_v,1)\otimes C&B_s\end{pmatrix},&c_h=0,\\[4pt]
\begin{pmatrix}\mathbf0&C\\\mathbf0&((w_v,1)\otimes C)\oplus B_s\end{pmatrix},&c_h>0.
\end{cases}
$$

其中 $\mathbf0=(\mathrm{INF},0)$ 表示不可行。矩阵乘法里的加、乘分别用 $\oplus,\otimes$，对应代码 `add`、`mul`。有限费用即使方案数取模后为零，也仍然可行。

一条链的矩阵从链头向链尾相乘。链尾一定是叶子 $t$，让它存单位矩阵，整条链乘积再作用于 $((0,1),(w_t,1))^T$，就得到链头的 `X/B`。查询与合并必须保持这个顺序。

代码中的主要字段如下：

| 字段 | 作用 |
| --- | --- |
| `low/high, leafId` | 节点的叶序区间、叶序到节点的映射 |
| `heavy/light, head, dfn, at, tail` | 重轻孩子、链头、链内连续编号、编号反查、链尾 |
| `X/B` | 动态传播时只需更新链头状态；轻孩子一定是另一条链的链头 |
| `heavyCount[v]` | 重孩子的需求次数，即 $c_{heavy[v]}$ |
| `rootCount` | 根自身的需求次数 |

`transition(v, lightPositive)` 就是上面的矩阵：重孩子状态由 `heavyCount[v]` 决定，轻孩子为零、为正的两种矩阵都能随时构造。

## 4. 将需求计数放到父亲处

每个非根节点的需求只保存一份：

- 重孩子的计数存在父亲的 `heavyCount` 中；修改后仅当零/正状态切换时重建父矩阵。
- 轻孩子的计数放在线段树的 `dfn[parent]` 位置，由线段树维护。
- 根的计数存在 `rootCount` 中。

因此修改某个规范节点时，`addNode(v, delta)` 为：

```text
p = parent[v]
若 p = 0：rootCount += delta
否则若 heavy[p] = v：修改 heavyCount[p]，必要时 pointRemake(dfn[p])
否则：rangeAdd(dfn[p], dfn[p], 轻孩子方向, delta)
```

方向约定为 `0=左，1=右`；父亲位置 `p` 的轻孩子方向即 `light[p] == rc[p]`。一条链内，路径经过重边时，所需的兄弟一定是轻孩子：把对应父亲位置做区间加减，并只修改指定方向。路径跨轻边时，兄弟变成重孩子，改一次 `heavyCount`。每条根路径只有 $O(\log n)$ 条轻边，点修改数量也就很少。

## 5. 线段树怎样一次改变很多矩阵

轻孩子的计数可能在一整段上同时从零变正，或从正变零。不能逐个重建矩阵。每个线段树节点保存代码中的三组字段：

```cpp
Matrix product[4];
int minimum[2], lazy[2];
```

对每个方向 $d$，`minimum[d]` 是这一段该方向计数的最小值。没有这个方向的位置时，用 `NO_COLOR` 表示不存在。所有计数非负，所以最小值为零时，恰好那些取最小值的位置需要使用“轻孩子计数为零”的矩阵。

`product[mask]` 保存一段矩阵乘积，`mask` 的两个二进制位分别控制两种方向：

- 第 $d$ 位为 `0`：该方向全部使用正计数矩阵；
- 第 $d$ 位为 `1`：该方向取最小值的位置使用零计数矩阵，其余仍用正计数矩阵。

例如一种方向的计数为 $[0,2,0]$，对应位为 `1` 的乘积使用“零、正、零”三种矩阵。整段加一后计数变为 $[1,3,1]$，取最小值的位置没变，保存的假想乘积也没变；只需把真实选择切换到该位为 `0` 的乘积。

### 整段加减：`tag` 和 `push`

整段同方向加 `delta` 不改变最小值位置，因此只改两个整数，不改任何乘积：

```text
tag(p, d, delta):
    若 minimum[p][d] = NO_COLOR：返回
    minimum[p][d] += delta
    lazy[p][d] += delta
```

下放时，把两个方向各自的 `lazy` 用同一个 `tag` 加给孩子，再清零。合法删除保证计数不会减成负数。

### 合并：`pull`

先分别求父区间的两方向最小值。某个孩子只有在自己的最小值等于父最小值时，才含有“父区间最小值位置”，允许继承对应的模式位。

```text
minimum[p][d] = min(minimum[left][d], minimum[right][d])
eligibleLeft  = 两个方向上，左孩子最小值等于父最小值的位集合
eligibleRight = 两个方向上，右孩子最小值等于父最小值的位集合
对 mask = 0..3：
    product[p][mask] = product[left][mask & eligibleLeft]
                       × product[right][mask & eligibleRight]
```

例如左孩子最小值为 $0$、右孩子为 $2$，父模式要求最小值位置用零矩阵时，只能给左孩子这一模式；右孩子必须使用全正模式。某方向不存在时，其模式位无作用，代码会直接复用清除该位后的乘积。

查询完整维护区间时，真实模式是

```text
mask = (minimum[0] == 0) | ((minimum[1] == 0) << 1)
```

返回 `product[mask]`；部分覆盖时递归查询并按从上到下的顺序相乘。

### 单点重建：`pointRemake`

重孩子计数过零，或者轻子链的 `X/B` 改变时，需要重建父亲位置。先沿途 `push`，到叶子后用 `transition(v, false/true)` 重建四种矩阵，再一路 `pull`。**保留这个位置已有的轻孩子计数与懒标记含义，不能重置为零。** 原树的叶子没有孩子，四种乘积都设为单位矩阵。

## 6. 一次增删操作怎样接起来

先找端点叶子的最高包含祖先：

```text
a = maximal(leafId[l], l, r)
b = maximal(leafId[r], l, r)
```

`maximal` 从当前链向上跳：若链头区间包含于 $[l,r]$，就尝试链头父亲；否则在链头到当前节点的 `dfn` 区间中，二分第一个完整包含的节点并返回。完整包含的条件是 `low[v] >= l && high[v] <= r`。只需最后一条链内二分一次。

若 $a=b$，只给它加一次计数。否则令 $z=LCA(a,b)$，除 $a,b$ 外：左边界上补右兄弟，右边界上补左兄弟，**排除父亲恰为 $z$ 的边**。前面的 $[2,7]$ 例子中，两侧分别补出 $[3,4]$ 与 $[5,6]$。

下面是与代码一致的边界更新。`rangeAdd(L,R,d,delta)` 在 $L>R$ 时不做事，`side` 返回孩子位于左侧还是右侧。

```text
boundary(v, z, d, delta):
    while depth[v] > depth[z] + 1:
        h = head[v]
        if h == head[z]:
            rangeAdd(dfn[z]+1, dfn[v]-1, d, delta)
            return
        rangeAdd(dfn[h], dfn[v]-1, d, delta)
        p = parent[h]
        if depth[h] > depth[z]+1 and side(heavy[p]) == d:
            addHeavy(p, delta)
        v = p
```

链内区间修改的是经过重边时的父亲位置；跨链处单独处理边 $(p,h)$。两个 `depth` 条件都用于排除 LCA 边。

直接改完这些计数后，还要把变化传回根。不要每做一次区间修改就单独向根传播。所有受影响矩阵都在 `parent[a]`、`parent[b]` 到根的两条路径上，先收集这些路径的链头，再统一处理：

```text
update(op, l, r):
    delta = (op == '+' ? 1 : -1)
    a = maximal(leafId[l], l, r)
    b = maximal(leafId[r], l, r)
    chains = parent[a] 到根经过的链头
    若 a != b：再加入 parent[b] 到根经过的链头

    addNode(a, delta)
    if a != b:
        addNode(b, delta)
        z = lca(a, b)
        boundary(a, z, 1, delta)   // 左边界补右兄弟
        boundary(b, z, 0, delta)   // 右边界补左兄弟

    将 chains 去重，按链头深度从大到小排序
    for h in chains:
        P = query(dfn[h], dfn[tail[h]])
        (newX, newB) = P × ((0,1), (weight[tail[h]],1))^T
        若 newX/newB 的费用和方案数都未变：继续
        X[h] = newX; B[h] = newB
        若 parent[h] != 0：pointRemake(dfn[parent[h]])

    输出 rootCount > 0 ? B[1] : X[1]
```

深链先完成，所以处理父链时，其轻子链已经报告了新状态。若此次只改根的计数，`chains` 为空，直接重新选择根的 `X/B` 即可。

## 7. 初始化与复杂度

先按真实树形做显式栈遍历，建立父亲、深度、从左到右的叶序；再逆序计算区间、叶子数及重轻孩子。节点编号任意，不能把编号倒序当作后序。

初始计数全为零，所有 $X_v=(0,1)$；叶子 $B_v=(w_v,1)$，内部节点计算

$$
B_v=(w_v,1)\oplus(B_L\otimes B_R).
$$

随后连续编号每条重链，确定 `head/dfn/at/tail`，在线段树各位置初始化方向最小值为零、不存在方向为 `NO_COLOR`，构造四种乘积。原树可能是长链，预处理使用迭代遍历；线段树递归深度只有对数级。

一次操作涉及 $O(\log n)$ 个链区间、点修改及待传播链，每项花 $O(\log n)$，因此总时间 $O(n+q\log^2 n)$，空间 $O(n)$（$n=1$ 时直接维护唯一节点需求）。费用用 `long long`，乘方案数用 64 位中间量。

## 8. 部分分路线

各档独立计分，按限制可逐步省去维护结构：

1. **5 分，$n\le7,q\le100$：** 枚举存储节点集合，用区间拼接可达性判断覆盖。
2. **10 分，$nq\le2\times10^6$：** 枚举规范块，每次全树重算 DP，$O(nq)$。
3. **10 分，精确中点分割：** 沿区间边界递归更新 DP，$O(n+q\log n)$。
4. **5 分，叶深不超过 $30$：** 同样沿实际边界更新，$O(n+30q)$。
5. **10 分，目标都是节点区间：** 计数点修改加普通动态树 DP，无须方向区间更新。
6. **10 分，左孩子均为叶子：** 内部节点只有一条链、一种方向，维护两种乘积即可。
7. **10 分，右子树不少于左：** 只有左侧轻孩子，保留多链传播，乘积只需两种。
8. **10 分，仅插入：** 有序集合跳过已激活的轻孩子位置，每点首次激活后删除，配合普通点修改动态树 DP。
9. **5 分，长度至多 $2$：** 按双叶组件计算局部费用与平局数，每次只改常数个组件，$O(n+q)$。
10. **25 分，无额外限制：** 使用完整算法。

第 8 档的所有激活方式须共用同一份标记；轻孩子若由端点点操作激活，也要从未激活集合删除。第 9 档跨组件的长度二目标会产生两个叶子需求，仍需维护引用次数。

## 附录：为什么上述维护正确

规范分解中的块两两无交。任何能参与目标精确覆盖的树节点，都落在唯一一个规范块内，所以覆盖原目标等价于覆盖全部规范块。最高包含祖先确定两端块，边界路径旁的内侧兄弟恰好补齐中间部分，排除 LCA 边后没有重复。

在每棵子树内，`X` 只合并两个孩子的实际需求；`B` 按是否购买当前节点分成两个互斥集合。正费用保证 `X` 不会额外购买当前节点，两个分支择优与计数均正确。矩阵只是同一递推的展开。

合法操作保持计数非负，零位置恰好由最小值判定；整段平移不改变最小值位置，四种假想乘积和 `pull` 的资格筛选因而始终有效。最后按深度处理链，每次都使用已更新的轻子链状态，根得到的就是当前全部需求的最优费用与方案数。
